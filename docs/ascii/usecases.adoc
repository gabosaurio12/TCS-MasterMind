
== Descripciones de Caso de Uso


*CU01 Crear Cuenta*

*ID:* CU01 +
*Nombre:* Crear Cuenta +
*Actor principal:* PLAYER +
*Actores secundarios:* SERVIDOR, CLIENTE (Juego WPF MasterMind) +
*Descripción:* Este caso de uso permite a PLAYER *crear una cuenta* del juego mediante la recopilación de su _Username_, _Email_ y _Password_ en el formulario de registro. El resultado es el *registro de la cuenta del PLAYER en la base de datos*. +
*Disparador:* PLAYER selecciona "Registrar" LoginPage +
*Precondiciones:* N/A

*Flujo Normal* +
1. El CLIENTE muestra la *SignupPage* al PLAYER. +
2. El PLAYER ingresa su _Username_, _Email_ y _Password_. +
3. El PLAYER selecciona "Registrar". +
4. El CLIENTE recupera de *SignupPage* los datos ingresados del PLAYER (_Username_, _Email_ y _Password_). +
5. El CLIENTE valida que ninguno de los datos esté vacío, que _Username_ y _Email_ tengan un formato correcto y que _Password_ cumpla con los requisitos de seguridad (ver FA01). +
6. El CLIENTE envía al SERVIDOR el _Username_ y el _Email_ para que valide su disponibilidad (ver EX01). +
7. El SERVIDOR regresa si _Username_ e _Email_ están disponibles (ver FA01)(ver EX01). +
8. El CLIENTE hashea la _Password_ (ver EX01). +
9. El CLIENTE envía _Username_, _Email_ y _Password_ al SERVIDOR para que registre al PLAYER (ver EX01). +
10. El SERVIDOR registra al PLAYER. (ver EX02). +
11. El SERVIDOR crea un código de verificación único y lo registra en la Base de Datos (ver EX02). +
12. El SERVIDOR envía el correo de verificación al _Email_ de PLAYER (ver EX03). +
13. El CLIENTE muestra *SuccessModal* informando a PLAYER que se registró su cuenta con éxito y que se envió un código de verificación a su correo electrónico. +
14. El PLAYER selecciona "Continuar" y el CLIENTE cierra *SuccessModal*. +
15. Incluye CU03. +
16. EL CLIENTE muestra *MainPage*. +
17. Termina el caso de uso.

*Flujos Alternos*

*FA01 - Datos inválidos* +
1. El CLIENTE muestra *ErrorModal* informando al PLAYER que algunos datos que ingresó son inválidos. +
2. El PLAYER selecciona "Continuar". +
3. El CLIENTE cierra *ErrorModal*. +
4. El CLIENTE actualiza el color de los campos de texto de los datos inválidos a color Rojo. +
5. El PLAYER corrige los datos inválidos. +
6. El PLAYER selecciona "Registrar". +
7. Regresa al flujo normal 4.

*Excepciones*

*EX01 - Error al conectarse con el Servidor* +
1. El CLIENTE recibe un FaultException. +
2. El CLIENTE registra en el Log la excepción. +
3. El CLIENTE abre *ErrorModal* informando al PLAYER que hubo un error al conectarse con el SERVIDOR. +
4. El PLAYER selecciona "Continuar". +
5. El CLIENTE cierra *ErrorModal*. +
6. Termina el caso de uso.

*EX02 - Error al conectarse a la base de datos*
1. El CLIENTE recibe un FaultException. +
2. El CLIENTE registra en el Log la excepción. +
3. El CLIENTE abre *ErrorModal* informando al PLAYER que hubo un error al conectarse con la Base de Datos. +
4. El PLAYER selecciona "Continuar". +
5. El CLIENTE cierra *ErrorModal*. +
6. Termina el caso de uso.

*EX03 - Error al enviar correo electrónico*
1. El CLIENTE recibe un FaultException. +
2. El CLIENTE registra en el Log la excepción. +
3. El CLIENTE abre *ErrorModal* informando al PLAYER que hubo un error al enviar el código de verificación y que debe comunicarse con el servicio técnico. +
4. El PLAYER selecciona "Continuar". +
5. El CLIENTE cierra *ErrorModal*. +
6. Termina el caso de uso.

*Postcondiciones:*
POST01: Se registró la cuenta del PLAYER en la base de datos +
*Reglas de negocio:* N/A +
*Incluye:* CU03 +

*Actores secundarios:* SERVIDOR, CLIENTE (Juego WPF MasterMind) +
*Descripción:* Este caso de uso permite a PLAYER *personalizar su perfil de usuario* que incluye cambiar _Username_ y _Email_. El resultado es que *personaliza sus datos*. +
*Disparador:* Selecciona "Actualizar" en *ProfilePage*. +
*Precondiciones:* PLAYER debe haber iniciado sesión con su cuenta.

*Flujo Normal* +
1. El CLIENTE muestra *UpdateProfilePage*. +
2. El PLAYER puede seleccionar "Cancelar" (ver FA01). +
3. El PLAYER puede cambiar su _Username_ en el UsernameTxt. +
4. El PLAYER puede cambiar su _Email_ en el EmailTxt. +

8.1. El CLIENTE agrega el nuevo _Username_ al objeto que se enviará al SERVIDOR para validar disponibilidad. +
9. SI PLAYER ingresó un nuevo _Email_ ENTONCES: +
9.1. El CLIENTE agrega el nuevo _Email_ al objeto que se enviará al SERVIDOR para validar disponibilidad. +
10. El CLIENTE envía el objeto con los cambios para validar su disponibilidad al SERVIDOR (ver EX01). +
11. El SERVIDOR regresa si _Username_ y/o _Email_ están disponibles (ver FA01)(ver EX02). +
12. El CLIENTE envía _Username_ y/o _Email_ al SERVIDOR para actualizar los datos de PLAYER en la base de datos (ver EX01).
13. El SERVIDOR actualiza los cambios de PLAYER. (ver EX02). +
14. El SERVIDOR crea un código de verificación único y lo registra en la Base de Datos (ver EX02). +
15. El SERVIDOR envía el correo de verificación al nuevo _Email_ de PLAYER (ver EX03). +
16. El CLIENTE muestra SuccessModal informando a PLAYER que los cambios se realizaron con éxito y que se envió un correo de verificación a su nuevo correo. +
17. Incluye CU03.

*Actores secundarios:* SERVIDOR, CLIENTE (Juego WPF MasterMind) +
